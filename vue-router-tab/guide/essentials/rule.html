页签规则 ​

APIDemo

页签规则定义了路由打开页签的方式，通过路由的 meta.routerTab.key 配置。

默认规则 ​

不配置 key 时，取当前层级的 matched.path，即同一路由共用同一个页签，params 与 query 变化都不新增页签。

内置规则 ​

内置规则只有两个：path 与 fullpath。规则名匹配大小写不敏感，因此 fullPath 与 fullpath 等价。

path ​

取 route.path。params 不同则独立开页签，query 变化不新增。

js
{
  path: '/my-page/:id',
  component: MyPage,
  meta: {
    routerTab: {
      title: '页面',
      key: 'path'
    }
  }
}

fullpath ​

取 route.fullPath。params 与 query 任一不同都独立开页签。

js
{
  path: '/my-page/:id',
  component: MyPage,
  meta: {
    routerTab: {
      title: '页面',
      key: 'fullPath'
    }
  }
}

  • /my-page/1?a=1 与 /my-page/1?b=2 → query 不同，独立页签

hash 参与 key 计算

fullpath 规则直接取 route.fullPath，hash 参与 key 计算 —— /my-page/1#a 与 /my-page/1#b 会开两个独立页签。若不希望 hash 参与区分，改用函数式 key 自行剥离。

自定义规则 ​

key 传字符串但不匹配内置规则名时，该字符串直接作为固定 key —— 所有命中该路由的地址共用一个页签：

js
meta: {
  routerTab: {
    key: 'my-fixed-tab'
  }
}

函数式规则 ​

key 传函数，入参为当前路由：

js
{
  path: '/my-page/:catalog/:type',
  component: MyPage,
  meta: {
    routerTab: {
      title: '定制规则',
      key: route => `/my-page/${route.params.catalog}`
    }
  }
}

函数不能返回内置规则名

函数的返回值会再走一遍规则表解析。若返回 'path' 或 'fullpath'，会被当成内置规则名，而不是你期望的固定 key：

js
// ❌ 返回值被当成内置规则名，实际等价于 key: 'path'
key: () => 'path'

// ✅ 需要固定 key 时换个不冲突的名字
key: () => 'my-path'

与缓存的关系 ​

页签 key 同时是缓存标识：key 相同则共用同一个组件实例与缓存。配合 keepAlive、reuse、maxAlive 可进一步控制缓存行为，详见页签缓存。
