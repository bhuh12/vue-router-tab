Nuxt ​

v2 暂不支持 Nuxt

v1 通过 $nuxt 特判适配 Nuxt 2（lib/util/RouteMatch.js 中在 Nuxt 环境下优先从页面组件的 meta 选项读取页签配置）。v2 已移除该特判，对 Nuxt 3 的支持待评估。

为什么移除 ​

v1 的适配依赖两个 Nuxt 2 特有机制：

  1. 页面级 meta 选项：Nuxt 2 允许在页面组件上直接写 meta，v1 通过 $nuxt.context.route.meta 数组回溯读取。Nuxt 3 改用 definePageMeta()，机制完全不同。
  2. extendRoutes 手动注入 iframe 路由：Nuxt 3 的路由由文件系统生成，扩展方式已变。

v2 的页签配置统一走 meta.routerTab（见入门），页面级动态信息走 useRouterPage()，两者都不再依赖框架特判。

SSR 的限制 ​

即使绕过上述配置差异，页签缓存本身与 SSR 存在冲突：

  • 缓存依赖 KeepAlive 与客户端组件实例的存活，服务端渲染阶段没有「页签历史」概念
  • 页签恢复（restore）依赖 sessionStorage，服务端不可用
  • iframe 页签只能在客户端挂载

因此即便未来适配 Nuxt 3，也只能以纯客户端插件方式运行（ssr: false 或包在 <ClientOnly> 内），这一路径尚未验证。

替代方案 ​

需要 SSR 的项目，建议只在后台管理区（通常不需要 SEO 与首屏 SSR）使用页签，将该区域配置为客户端渲染。

如果你在 Nuxt 3 下成功接入，欢迎在 GitHub Issues 反馈实践方案。
