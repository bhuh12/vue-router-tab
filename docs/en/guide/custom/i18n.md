Internationalization has two parts: **the component's own text** (the `lang` prop) and **business text like tab titles** (the `i18n` prop).

## Component Text: lang

`lang` is typed `string | Record<string, any>`, defaulting to `'auto'`.

### Built-in Languages

There are **only two** built-in languages: `zh` and `en`.

```vue
<template>
  <RouterTab lang="en" />
</template>
```

<DocLinks :demo="DEMO_ROUTES.LangEn" />

### Auto Detection

When `lang="auto"` (the default), the first two characters of `navigator.language` are used; if it doesn't match a built-in language, it **falls back to `en`**:

```js
// navigator.language = 'zh-CN' → 'zh' → matches built-in zh
// navigator.language = 'ja-JP' → 'ja' → no match, falls back to en
```

### Custom Language Object

When passing an object, the full structure must be provided:

```vue
<template>
  <RouterTab :lang="myLang" />
</template>

<script setup>
const myLang = {
  tab: {
    untitled: '無題'
  },
  contextmenu: {
    refresh: '更新',
    refreshAll: 'すべて更新',
    close: '閉じる',
    closeLefts: '左側を閉じる',
    closeRights: '右側を閉じる',
    closeOthers: '他を閉じる'
  },
  msg: {
    keepLastTab: '少なくとも1つのタブを保持してください',
    i18nProp: '"i18n" メソッドを提供してください'
  }
}
</script>
```

::: warning The Lang Type Isn't Exported
The library doesn't export a `Lang` type; when writing a custom language object, declare the structure yourself, or copy the fields from the example above.
:::

Field list (9 total):

| Path                      | Description                                              |
| ------------------------- | -------------------------------------------------------- |
| `tab.untitled`            | Placeholder text for untitled tabs                       |
| `contextmenu.refresh`     | Context menu "Refresh"                                   |
| `contextmenu.refreshAll`  | Context menu "Refresh All"                               |
| `contextmenu.close`       | Context menu "Close"                                     |
| `contextmenu.closeLefts`  | Context menu "Close Left"                                |
| `contextmenu.closeRights` | Context menu "Close Right"                               |
| `contextmenu.closeOthers` | Context menu "Close Others"                              |
| `msg.keepLastTab`         | Message shown when attempting to close the last tab      |
| `msg.i18nProp`            | Warning text shown when the `i18n` method isn't provided |

## Business Text: i18n

Text like tab titles that comes from route `meta` is handed off to your i18n library via the `i18n` prop:

```ts
i18n?: (key: string, params?: unknown[]) => string
```

### Integrating with vue-i18n

```vue
<template>
  <RouterTab :i18n="translate" />
</template>

<script setup>
import { useI18n } from 'vue-i18n'

const { t } = useI18n()

function translate(key, params) {
  return t(key, params)
}
</script>
```

### Marking i18n Keys in meta

Two ways to write it:

```js
// 1. String form: `i18n:` prefix
meta: {
  routerTab: {
    title: 'i18n:route.userList'
  }
}

// 2. Array form: first item is the key, the rest are params
meta: {
  routerTab: {
    title: ['route.userDetail', 'Alice']
  }
}
```

Plain strings without the `i18n:` prefix are displayed as-is, without going through translation.

::: warning Key Configured but No i18n Method Passed
The component logs a console warning once (using the `msg.i18nProp` text) and displays the key as-is.
:::

### Dynamic Titles Are Supported Too

The return value of a function-style `title` also goes through i18n resolution:

```js
meta: {
  routerTab: {
    title: (route) => ['route.page', route.params.id]
  }
}
```

## Manual Invocation

`useRouterTab()` exposes `i18nText` and the current language pack:

```js
const tabs = useRouterTab()

tabs.i18nText('i18n:route.userList') // goes through the i18n method
tabs.i18nText('plain text') // returned as-is
tabs.langs.tab.untitled // read the current language pack
```

This is useful in the dynamic text of [custom context menu items](./contextmenu#menu-text-internationalization).

## Switching Languages

The component's language reacts to changes in the `lang` prop — just drive it with a `ref`:

```vue
<template>
  <RouterTab :lang="lang" />
  <button @click="lang = 'en'">English</button>
</template>

<script setup>
import { ref } from 'vue'

const lang = ref('zh')
</script>
```
